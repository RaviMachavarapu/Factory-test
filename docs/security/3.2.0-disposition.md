# Security Disposition — v3.2.0

This file disposes of the 18 findings in `docs/security/3.2.0-review.md`.

  never accepted or deferred. The `build/sec-SEC-004` back-edge, PR #61,
  merged on 2026-10-03 as `33a4984`, and the entry below is `fixed`.

  2026-10-03 to raise the cap to 10 for this release by its own reviewed PR,
  PR #59, which records the decision in `docs/security/RUBRIC.md` and
  returns the cap to 5 by 2026-10-12 unless the P7 retrospective re-decides
  it. The override record lists the nine ids, and
  `tests/governance/test_security_schema_docs.sh` pins that the accepted or
  deferred mediums of this pair are exactly those nine, so a tenth accepted
  medium is a reviewed change to `main`'s RUBRIC.md, never this branch's.
- SEC-005 (medium) stays `open` with no disposition decided. SEC-020
  (medium), from the back-edge's own review, stays `open` for the reason
  above: its fix is owed to P7 Build 1, and the P7 retrospective decides
  whether to accept it under a re-decided cap instead. An open medium does
  not count against the cap, and both are named as open in the release
  notes and known-limitations.

The accepted entries carry the owner and expiry that the threat model
records for each residual. The deferred entry, SEC-006, carries the P7
retrospective's date, which PR #56 verifier run 1, finding 5 gave to every
P6 residual. SEC-021, raised by PR #61 verifier run 1, carries the same
date.
