You are running a retrospective (`art-retrospective-cadence`).

Create a new branch: `phase/retro-$(date +%Y-%m-%d)` from main.

Read:
1. `docs/postmortems/` (if present) — production bugs and incidents.
2. `docs/plans/*/notes/` (if present) — recurring blockers and discoveries.
3. The last RELEASE notes and known-limitations docs.
4. `docs/BACKLOG.md` — every deferred proposal, by id.

Produce `docs/retrospectives/$(date +%Y-%m-%d)-$ARGUMENTS.md` with YAML frontmatter (`date`, `triggered_by: release | adhoc`, `release_version` if applicable, `proposes_changes_to: [<file-paths>...]`) and body sections: ## What Worked, ## What Didn't, ## Proposed Changes, ## Decisions on Prior Proposals, ## Open Questions.

The output **proposes** changes. It does not edit constitution.md or templates directly. Apply accepted proposals in a follow-up PR.

**Bump the pinned tool downloads (mandatory, REQ-334):** `## Proposed Changes`
must propose, as its own item, the bump of every pinned download that
Dependabot does not watch:
- `scripts/pinned-tools.yml` — new sha256 values from each tool's release
  checksum file (Dafny's sha256 is computed from the asset, since Dafny
  publishes no checksum file);
- the pack pins in `stacks/*/pack.yml` (including `cargo_audit_version`),
  with the lockfiles regenerated by pip-compile or uv;
- the SHA-pinned actions in `stacks/*/action.yml` and `stacks/*/release/action.yml` (and, in an instance,
  `.github/actions/toolchain/action.yml` and `.github/actions/release/action.yml`) — Dependabot watches only
  `.github/workflows/`, never the pack composites, so these pins are bumped
  by hand here;
- the python pack's base image digest, `python:3.12-slim@sha256:…` in
  `stacks/python/Dockerfile` (in a python instance, `Dockerfile`) — no
  Dependabot ecosystem watches it, so it is re-pinned by hand from
  `docker buildx imagetools inspect python:3.12-slim` (owner: the maintainer,
  kpingali123; re-pinned 2026-10-04, its own re-pin deadline 2027-02-13), since
  the pinned base keeps its OS packages' published CVEs until it moves;
- the re-enumeration of `osv-scanner.toml` and `audit.toml` suppressions
  against their disposition;
- the expiry of every pack-shipped skeleton disposition entry
  (`stacks/*/overlay/docs/security/*-skeleton-disposition.md`; tauri's
  accepted entries expire 2027-03-24, renewed on 2026-10-04) — re-pin and
  re-enumerate, then renew or fix the
  entries before the date, or every new instance's floor fails. Owner: the
  maintainer, kpingali123; re-pin deadline 2027-02-13. The date does not
  wait for a retrospective, so these triggers exist:
  `tests/governance/test_suppression_expiry.sh` warns in every gates run
  from 2027-01-23 and fails the template's gates from 2027-02-23 (under 30
  days); the weekly schedule of `.github/workflows/app-stacks.yml` runs the
  tauri first run (its gates run the floor) and goes red at its first run
  on or after 2027-03-24. A
  tauri instance scaffolded after 2027-03-24 fails its first gates run until it renews
  (README "Known limitation" gives the instance's renewal steps).

**Closing the loop (mandatory):** Walk every id `docs/BACKLOG.md` lists with **Status:** open and record one line per id in `## Decisions on Prior Proposals`, exactly `- BL-NNN: accepted (landed: <PR/commit>) | accepted (target: <PR/owner>) | rejected (<why>) | deferred (<trigger>)`; in the same PR, mark each decided entry `**Status:** decided` with its `**Decision:**` line naming this retrospective's file, and add every new proposal this retrospective defers as a new `BL-NNN` (the next unused number; create `docs/BACKLOG.md` from `templates/BACKLOG.md` if it is absent) (REQ-371).
In `## Decisions on Prior Proposals`, also walk every
proposal from the previous retrospective and record a decision line:
`accepted (landed: <PR/commit>) | accepted (target: <PR/owner>) | rejected (<why>) | deferred (<trigger>)`.
A proposal without a recorded decision carries forward and must be re-listed.
When this retrospective's own proposals are later decided, append the decisions
to THIS document in the follow-up PR rather than leaving them implicit.

Push and open PR per `.claude/rules/review-gate.md`.
