# Security Disposition — v0.0.0-skeleton

This is the tauri pack's skeleton disposition (REQ-388, R12): it defines the
`SEC-NNN` ids that `src-tauri/audit.toml` and `osv-scanner.toml` cite for the
advisories still present in the pinned Cargo/npm lockfiles at pin time
(measured 2026-09-25/26 with cargo-audit 0.22.2 and osv-scanner 2.6.0: seven
advisories, eight ids counting glib's GHSA alias; re-enumerated on 2026-10-02
with the same versions after the yanked `yoke-derive` 0.8.3 was moved to 0.8.4,
`src-tauri/Cargo.lock` sha256 5871b662…, no entry changed). The pinned-download
bump (`patch/pin-bump-2026-11`; retrospective 2026-10-04-v3-2-closeout.md,
Proposed Changes item 1) regenerated both lockfiles, and they were
re-enumerated on 2026-10-04 with cargo-audit 0.22.2 and osv-scanner 2.6.0
against `src-tauri/Cargo.lock` sha256
21b14f9e7b5adc3422fcb8eeb0dae5dabd7477d033d42d6f437ba9c4a21405c5 and
`package-lock.json` sha256
295d0757da494b4b493306995f6e43aa283f0c18f5167f7cd1803db115ddbc6f: SEC-001 and
SEC-002 remain (renewed below), and SEC-003's five advisories are gone
(`urlpattern` 0.6.0 no longer pulls the `unic-*` family), so SEC-003 is
`fixed` and its ignores are dropped; its id is kept (see
`0.0.0-skeleton-review.md`). `init` copies both this file and the review into
every scaffolded tauri instance, so the instance's first `/security-review`
carries these three entries forward and numbers its own findings from
SEC-004 (ADR-002 rule 4).

These are the pack's risk acceptances, not the instance maintainer's: each
entry is owned by `tauri-pack` and marked `inherited:`. The instance's first
`/security-review` must set `owner:` to its own maintainer and confirm,
change or fix each entry. The two accepted entries, SEC-001 and SEC-002,
expire on 2027-03-24 (each `expiry:` below; renewed on 2026-10-04 from
2026-12-24); after that date the floor fails by design
(calendar-triggered, so the risk is re-accepted), and the first
`/security-review` after that date must refresh or fix both. ADR-002
rule 4 covers SEC-001 (medium): a prior accepted entry of medium or above
whose expiry has passed must now be `fixed` or re-accepted with a fresh
expiry, and `check-security-disposition.sh` fails the ship PR otherwise.
Rule 4 does not reach lows: the floor's `ignoreUntil` date alone covers
SEC-002 (low) — once it passes, the floor fails until the
suppression is renewed or the dependency fixed. A template re-pin never reaches an existing instance, so the
instance renews them itself: bump `ignoreUntil` in `osv-scanner.toml` and in
each `src-tauri/audit.toml` entry's trailing comment, and add entries under
the instance's own version (`docs/security/<version>-disposition.md`, with
an `expiry:` no earlier than the new `ignoreUntil`).
